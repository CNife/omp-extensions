# 子进程错误只静默吸收「进程已退出」

plannotator-cli 的写 stdin、强制结束、读 stderr 都可能失败。此前这些 `catch` 不区分原因一律吞掉，注释用「子进程可能已退出」为全量吞错开脱；权限问题、参数错误、运行时行为变化都被静默吸收，排障时没有任何痕迹（[#132](https://github.com/CNife/omp-extensions/issues/132)）。

## 判定

- 结束前先看 `proc.exitCode` / `proc.signalCode`：已退出就不发信号，这是正常路径。
- 真的发信号却报错时，只有 `EPIPE` / `ESRCH` 当作「进程已退出」的竞态；其余原因打一条 `console.warn`，不打断反馈投递。
- stdin 写入与关闭、stderr 读取失败同此分类。

## 为什么实测「不抛」还保留兜底

Bun 1.4.3 上对已退出进程发信号不抛，FileSink 写入也不抛，这些 catch 在当前运行时几乎碰不到。保留是因为这些行为随运行时版本变过，而插件跟随宿主运行时升级；哪天真抛出来，必须能被看见。

## 收尾宽限

拿到完整决策后不再立刻强杀：决策是上游进程的最后一个动作（`completeAnnotateCommand` → 结算 → 关服务 → 写决策 → 退出），插件先投递，再等最多 3 秒让它自己退出，仍不退才强杀并留痕。超时路径不复用这段宽限——那 30 分钟本身就是宽限，超时提示已说明原因。

## 未采用宿主关闭

上游提供 `PLANNOTATOR_SESSION_BRIDGE_TOKEN` + `POST /api/host/close`，让宿主把会话按「用户关闭」结束并保留草稿。它需要就绪文件、令牌、旧版本回退三类机制，本插件暂不采用，超时仍以强杀收尾。
