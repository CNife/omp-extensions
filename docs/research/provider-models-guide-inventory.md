调查对象：旧技能 `plugins/howto-skills/skills/add-provider-models/` 与 omp v18.3.0 当前文档/源码，并筛查 coding-agent、catalog 的 v18.0.8→v18.3.0 changelog。范围是配置自托管/兼容 API 的 provider 与 model；不是替主仓库改动。除共享 artifact 外未写文件。

> **2026-10-08 基线刷新**：omp 已演进到 v18.8.3（对照源码 `/home/cnife/github/can1357@oh-my-pi`，tag v18.8.3）。下文前四个章节是 18.3.0 基线的原始盘点，保持不动；文末新增「18.3.0 → 18.8.3 变更重盘」与「#92 十一条结论重验」两章，后续写作工单应以刷新章为准、18.3.0 章为历史参照。

## 旧技能中需要改写或加限定的说法

1. **固定配置路径不是唯一位置。** 旧技能把 `~/.omp/agent/models.yml` 当唯一目标（`SKILL.md:17,75-78`）。这是默认路径，不是硬编码的唯一位置；文档也列 `models.yaml` 与旧 `models.json` 迁移、程序化 `.json/.jsonc` 路径。源码由 `getAgentDir()` 推导默认目录，故 `PI_CODING_AGENT_DIR` 会重定位 agent 目录；具体写入前先定位运行实例的目录。证据：`omp://models.md §Config file location and legacy behavior`; `/home/cnife/github/can1357@oh-my-pi/packages/coding-agent/src/config/model-registry.ts:430`; `.../src/cli/help-extra.ts:66`。

2. **`models-dev-query` 不是 OMP 的必经配置接口。** 旧技能将其列为必须流程，并让其与官方厂商文档形成固定优先级（`SKILL.md:23-28,42`）。OMP 文档描述的是：已知 provider 的共享 models.dev 数据可供合并/补元数据；这不是 provider 端点/账户可用性的权威来源，也不构成要求调用名为 `models-dev-query` 的工具。当前实际 `/models` discovery/端点约束才用于发现 endpoint 上可用模型。证据：`omp://models.md §Merge and override order`, `§Shared catalog refresh`, `§Runtime discovery integration`; `omp://provider-endpoint-constraints.md §Baseline rules`。

3. **只看 `baseUrl` + `api`、并只在已知例外时看 endpoint 约束，不够。** 旧技能关于“按 API 而非厂商名称”选择协议的方向正确，但 canonical provider key、gateway/auth、model-level compat、调用上下文都会改变行为；应从一开始检查 endpoint-constraints。wire ID 也未必等于配置 `id`（Azure/OpenRouter 等会映射/改写），所以旧验证中的 `jq .request.payload.model == $model` 只能用于端点确实保留 ID 的情形，不能作为通用失败判据。证据：旧 `SKILL.md:11,23-25,35,39`; `references/verification.md:28-30`; `omp://models.md §models.yml / models.yaml shape`, `§Provider and model identity`, `§Compatibility and routing fields`; `omp://provider-endpoint-constraints.md §Baseline rules`, `§Choose the endpoint family first`, `§Apply gateway and auth overlays`, `§Azure OpenAI`, `§OpenRouter`。

4. **Thinking schema 不等于 wire 字段清单。** 旧文把 `thinking.efforts` 写成可独立使用的字段，并把 `mode: budget` 当 provider 风格语法（`SKILL.md:50-53`; `references/thinking-adaptation.md:21-25`）。v18.3 schema 要求 `thinking.mode`；mode 包括 `effort`、`budget`、`google-level`、`anthropic-adaptive`、`anthropic-budget-effort`；需要 `efforts` 或受支持的 legacy tier 字段。`effortMap` 还可定义在 model.thinking；`compat.reasoningEffortMap` 是另一层。`thinking_budget` 等 wire 参数不是 `models.yml` thinking 字段。Qwen 可用顶层 `enable_thinking` 或 `qwen-chat-template` 的 `chat_template_kwargs.enable_thinking`；OFF 行为由具体 compat/endpoint 规则决定，不能泛化为 thinkingFormat 自动处理。证据：旧 `references/thinking-adaptation.md:11-25`; `/home/cnife/github/can1357@oh-my-pi/packages/coding-agent/src/config/models-config-schema-bundle.ts:110-150`; `omp://models.md §Compatibility and routing fields`; `omp://provider-compat-reference.md §1 OpenAI compat flags → Reasoning wire format`, `§2 Reasoning levels → The effort model`, `Per-provider wire mapping`, `The OpenAI-compat resolution pipeline`; `omp://provider-endpoint-constraints.md §Map reasoning and thinking explicitly`。

5. **Model metadata / cost 的边界需说清。** `input: [text, image]` 仍是模型 schema 支持的两类；但声明 image 不保证图片真送达（例如 compat 可剥除图片）。若显式写 `models[].cost`，input/output/cacheRead/cacheWrite 四项都必填；遗漏会令整份自定义 models config 无效（本轮已知实测，且 schema 要求四项）。model definition 的 cost 是平面费率覆盖，不是 FX 换算规范；`timeBased` 不能写进 YAML，缺省 cost 可能继承 shared catalog 价格，未知代理可能保持本地未知/零价。旧摘要还漏掉 `maxContextWindow` / `/extended-context`：它改变 OMP 本地预算，不会抬高服务端限制；要验证 endpoint 接受较大请求。证据：旧 `SKILL.md:41-44,65-67`; `/home/cnife/github/can1357@oh-my-pi/packages/coding-agent/src/config/models-config-schema-bundle.ts:193-214`; `omp://models.md §Model value checks`, `§Usage costs and time-based pricing`, `§Compatibility and routing fields`; `omp://provider-endpoint-constraints.md §Preserve usage and cost semantics`; `omp://models.md §models.yml / models.yaml shape`（maxContextWindow说明）。

6. **`--config` 临时文件不是全隔离环境；捕获手段也需区分。** 旧 `references/verification.md:13-33` 对 `--no-extensions`、显式 `--extension`、`--no-skills --no-rules` 的用法方向仍可用，当前 CLI 仍有这些参数；但临时 cwd/`--config` overlay 不会抹掉已加载的全局与项目配置，overlay 是在它们之后应用，不可宣称“避免全局配置”。历史上 v18.0.8 的经验也不能充当 v18.3 行为证据。extension `capture.ts` 仍在仓库，但它记录的是摘要而非原始响应 body，且源码注释指出没有 Authorization、responseModel 为 null、日志未脱敏；v18.3 原始 HTTP 报文可用 `PI_REQ_DEBUG=1` 记录到当前 cwd 的 `rr-session-N.json` 和 `.res.log`，包含敏感 headers/body，不能提交或公开。证据：旧 `references/verification.md:13-33`; `/home/cnife/github/can1357@oh-my-pi/packages/coding-agent/src/cli/args.ts:268-277`; `.../src/cli/flag-tables.ts:117-119,216-217,315-317`; `.../src/main.ts:1585-1595,1622-1624,1720-1725,1747-1749`; 仓库 `plugins/howto-skills/extensions/capture.ts:16-28,94-112,139-185`; `/home/cnife/github/can1357@oh-my-pi/packages/ai/src/utils/request-debug.ts:48-70,80-97,208-220`; `.../src/utils/transport-fetch.ts:37-39`。

7. **不能把四种能力测试都要求为每个模型通过。** 旧 `SKILL.md:128-131` 与 `references/verification.md:42-86` 把 HTTP 200、thinking、tools、cache 都列为普遍通过条件。应按 endpoint/model 声明的能力建立测试矩阵；不支持工具、reasoning 或缓存的模型不应因对应项 N/A 被判配置坏。一个 200 也不是能力/usage 语义证据；错误状态可能是认证或 discovery 问题。捕获里的 thinking JSONPath 也不覆盖 chat-template / Google 等 wire shape。旧技能的“最多三次重试”及“只改 models.yml”属于局部流程约定而非 OMP 契约。证据：旧 `SKILL.md:82,124-145`; `references/verification.md:35-86`; `plugins/howto-skills/extensions/capture.ts:16-28,94-112,139-185`; `/home/cnife/github/can1357@oh-my-pi/packages/coding-agent/src/config/models-config-schema-bundle.ts:195-205`; `omp://provider-compat-reference.md §1 OpenAI compat flags → Sampling, tokens, caching, routing`; `omp://provider-endpoint-constraints.md §Preserve usage and cost semantics`, `§Checklist for a new constraint`。

8. **文档与 schema 有两处应明确披露的差异。** 文档说 custom `auth: oauth` 不免 `apiKey`，但当前实现的 models-config 验证器把 `oauth` 也作为不要求 apiKey 的例外；这只证明 schema 接受配置，不证明任意 provider 已有可用 OAuth 登录/令牌流程。文档的 discovery 值清单也未列 `apple-foundation-models`，而当前 schema 枚举包含它；该类型对应 v18.3 Apple Foundation Models 内建发现，不应因此假定一般远端自定义 provider 可随意使用它。冲突以源码为准并限定其语义。证据：`omp://models.md §Allowed auth/discovery values`; `/home/cnife/github/can1357@oh-my-pi/packages/coding-agent/src/config/models-config.ts:64-67`; `.../src/config/models-config-schema-bundle.ts:292-305`; `/home/cnife/github/can1357@oh-my-pi/packages/coding-agent/CHANGELOG.md:21-23`。

## 仍然成立、可保留的核心

- 默认首选路径仍是 `~/.omp/agent/models.yml`；provider key 是身份标识，`provider/model-id` 可消除选择歧义。`omp://models.md §Config file location and legacy behavior`, `§Provider and model identity`。
- 对兼容端点按真实 API family 定义 `api`，核对精确 model ID、输入能力、contextWindow/maxTokens、成本与 compat；model compat 是有目的的 endpoint-specific override，不是随便加开关。`omp://models.md §Provider-level fields`, `§Validation rules (current)`, `§Compatibility and routing fields`。
- `omp models <provider>` 可观察可见模型/执行 discovery；但可见性不等价于请求成功、模型 capability、request wire shape 或账单语义。`omp://models.md §Runtime discovery integration`, `§Model availability vs all models`, `§/model and omp models`; `omp://provider-endpoint-constraints.md §Baseline rules`。
- local role assignment（`local/<model-id>`，如 memory/small/speech）和 `models.yml` 自定义 provider 是不同配置面。`omp://local-models.md §Integration notes`; `omp://models.md §Runtime discovery integration`。

## 新技能应明确写进的操作性陷阱

1. 每次先确定目标是用户的 `models.yml` 还是 omp 内建 catalog；先查已内建 provider，避免把 provider 开发任务写成用户配置工作。`omp://models.md §Config file location and legacy behavior`; `packages/catalog/CHANGELOG.md:129-141`。
2. 用 `getAgentDir()` / 实际运行环境确定配置位置；“默认路径”不得写成唯一目录。`omp://models.md §Config file location and legacy behavior`; `.../src/config/model-registry.ts:430`; `.../src/cli/help-extra.ts:66`。
3. 先按 provider/model schema 配置，再逐项增加 compat；`models[].cost` 四字段齐全；把 `/extended-context` 当本地预算而非端点能力证明。`omp://models.md §Validation rules (current)`, `§Usage costs and time-based pricing`, `§models.yml / models.yaml shape`; `models-config-schema-bundle.ts:193-214`。
4. 将 reasoning capability、effort tiers、映射、wire serialization 分开核验；至少检查当前模型实测请求，而不是只查一个 JSONPath。`omp://provider-compat-reference.md §2 Reasoning levels`; `omp://provider-endpoint-constraints.md §Map reasoning and thinking explicitly`。
5. discovery endpoint 与 inference endpoint 分别验证；记下是否注入 `/v1`、代理是否重写 model ID、认证/header 的来源与响应错误。`omp://models.md §Runtime discovery integration`, `§Allowed auth/discovery values`; `omp://provider-endpoint-constraints.md §Choose the endpoint family first`, `§Apply gateway and auth overlays`。
6. 对工具、thinking、image、cache、usage 验证仅测试 endpoint 已声明/承诺的能力；没有支持的能力明确标 N/A，而不是判失败。`omp://provider-endpoint-constraints.md §Preserve usage and cost semantics`; `omp://provider-compat-reference.md §1 OpenAI compat flags → Sampling, tokens, caching, routing`。
7. `PI_REQ_DEBUG=1` 是 raw wire 证据但带敏感 headers/body；限制到临时 cwd，结束后清理，禁止提交日志。旧 capture extension 不是 raw response/auth 记录器。`packages/ai/src/utils/request-debug.ts:48-70,80-97,208-220`; `plugins/howto-skills/extensions/capture.ts:21-28`。
8. `/dump` 是交互 slash command，不是 `omp -p` 的执行方式；需要导出 session 时在支持 slash 路由的交互面使用。`omp://session-operations-export-share-fork-resume.md §/dump`; `omp://slash-command-internals.md §5 Routing and prompt-pipeline placement`。本轮已知实测：`omp -p "/dump"` 不会执行 slash command。
9. 将 `local/<model>` 的 memory/small/speech role 说明与 `models.yml` endpoint 配置分开。`omp://local-models.md §Integration notes`。

## 18.3.0 → 18.8.3 变更重盘（provider/model 配置相关）

证据基线：omp 源码 tag `v18.8.3`（`/home/cnife/github/can1357@oh-my-pi`）；changelog 为 `packages/coding-agent/CHANGELOG.md` 与 `packages/catalog/CHANGELOG.md` 中 18.3.1 → 18.8.3 各版本条目（以 `[18.x.y]` 标题定位）。schema 层面用 `git diff v18.3.0 HEAD -- packages/coding-agent/src/config/models-config-schema-bundle.ts` 确认，未凭 changelog 猜测字段。

### models.yml schema 字段变化（18.3.0 → 18.8.3 全部 diff 所得）

- **model/modelOverrides 新增 `promptCache`（`short`/`long`，秒）**：显式 `promptCache` 整体替换 catalog 生存期而非合并；`promptCache: {}` 关闭该模型的 cache warming。v18.3.5 引入（catalog changelog `[18.3.5]`）。证据：`models-config-schema-bundle.ts:220-223,279-282`；`omp://models.md §Prompt cache lifetimes`。
- **compat 新增 `statefulResponses`**：按 provider/model 显式选择/退出 Responses `previous_response_id` 链式，优先级为 call option > `PI_OPENAI_STATEFUL` > `compat.statefulResponses` > `compat.officialEndpoint`。v18.6.3 引入。证据：`models-config-schema-bundle.ts:74`；`omp://models.md §Compatibility and routing fields → statefulResponses`。
- **compat 新增 `bedrockMessagesApi`**：为 `anthropic-messages` 模型启用 Bedrock `/anthropic` 路线行为（去 tool `strict`、适配 `metadata.user_id`、on-demand compaction）；从 Bedrock `/anthropic` baseUrl 自动检测，也可显式置 true/false。v18.4.4 引入。证据：`models-config-schema-bundle.ts:87`；`omp://models.md §Claude on Bedrock's Anthropic Messages API (/anthropic)`。
- **compat 新增 `supportsSteering`**：Codex WebSocket `response.steer`（GPT-6 家族默认开）；拒绝该事件的代理显式置 false。证据：`models-config-schema-bundle.ts:85`；`omp://models.md §Compatibility and routing fields → supportsSteering`。
- **新增 runner API / `kind` 维度**：model 与 modelOverrides 的 `api` 从纯 chat API 枚举扩展为可引用 runner API（`openai-images`、`openai-embeddings`、`openai-speech` 等），并新增 `kind` 字段（`chat`/`image`/`embedding`/`tts`/…）；显式 `kind` 必须是其 api 能服务的 kind，验证器新增 `checkKind`。v18.7.0「custom model-kind declarations for providers and extensions」落地。证据：`models-config-schema-bundle.ts:110-118,208-209,268-269`；`models-config.ts:92-121`；`omp://models.md §Allowed provider/model api values`。
- **除上述外，`cost`/`input`/`thinking`/`discovery`/`auth`/`transport` 等既有字段枚举与必填性零变化**（diff 仅含上列新增与 `api` 重构）。`models[].cost` 仍四项全必填、`modelOverrides.cost` 仍全可选。

### 验证与运行时行为变化

- **未知 compat key 警告（18.8.1）**：provider/model/modelOverrides 的 `compat` 块中出现 schema 与运行时 wire 词表都不认识的键，产生非致命警告（交互启动通知、print/RPC/`omp models` stderr），配置照常加载，键被保留。运行时词表不按 provider 的 `api` 过滤。证据：`omp://models.md §Unknown compatibility keys`；`models-config.ts`（`getUnknownCompatKeys`）；coding-agent changelog `[18.8.1]`。
- **模型恢复失败改为显式报错（18.6.3，Breaking）**：resume 时保存的 model 无法恢复，`createAgentSession`/`switchSession` 抛 `Could not restore model <provider/id>`（有 UI 且 `retry.modelFallback` 开时仍降级警告；无 UI host 可用 `allowSessionModelFallback: false` 退出降级）。打印/RPC 模式启动即报错退出。旧技能若写「resume 静默回退到默认模型」即过时。证据：coding-agent changelog `[18.6.3] Breaking Changes`。
- **`supportsImageDetailOriginal` 默认值收紧（18.6.3）**：OpenAI/Azure/Codex 之外的自定义、本地、xAI、Copilot 等 Responses 端点默认 `false`，snapcompact 帧与 computer 截图改发 `detail: "auto"`；自定义 host 需 `compat.supportsImageDetailOriginal: true` 显式加入。证据：catalog changelog `[18.6.3]`；`omp://models.md §Compatibility and routing fields → supportsImageDetailOriginal`。
- **DSML 工具调用在所有 host 解析（18.6.0）**：包括 llama.cpp/LM Studio/vLLM 本地端点、`models.yml` 自定义 provider 与不在旧名单上的网关；完整 `<｜DSML｜tool_calls>` 信封不再以纯文本出现。证据：catalog changelog `[18.6.0]`；schema 新增 `streamMarkupHealingPattern` 相邻语法的运行时词表支持（`omp://models.md §Compatibility and routing fields → streamMarkupHealingPattern`）。
