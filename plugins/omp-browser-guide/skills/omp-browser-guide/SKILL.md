# omp-browser-guide

本技能把使用 omp browser 的通用方法论前置：任务分层、成本结构、状态管理、能力分层。

## 心智模型

### 任务分层：先问"我要哪一层"

浏览器任务分三类，决定从哪层开始：

- **取数据** → 网络层：挂 `page.on('response')` 抓 API 响应。DOM 是渲染结果，不是数据源。
- **理解页面** → DOM 层：`observe` 拿无障碍树，`ariaSnapshot` 拿 ARIA 结构。
- **操作页面** → 交互层：`click`/`type`/`select`/`press`。

别默认从 DOM 开始——任务类型决定层，不是工具列表决定路径。

### 成本结构：观察贵，操作便宜

- 每次 observe/截图/读 DOM 都消耗上下文，操作本身便宜。
- 一次拿全量：循环、批量、数据处理在 `code` 里一次写完，不拆多轮。
- 等条件用 `wait(fn)` 轮询、等响应用 `waitForResponse`，不固定 sleep。
- 每页调用超过 10 次说明你在 scraping 而不是 interacting——考虑走网络层或一次 code 拿全量。
- 截图是给人类的：烧 token 少信号，除非页面真是视觉的（验证码、图表）。

### 状态管理：页面是活的

- tab 跨调用存活，页面随时会变（导航、SPA 更新、re-render）。
- 操作前确认状态，操作后验证结果。
- 句柄/ref 会失效，re-render 后重新获取。
- 更危险的是静默错配：页面变化后旧 ref 可能匹配到新页面上形状相似的元素——导航后不要复用旧 ref。

### 能力分层：从够用的最低层开始

- `tab` helper → `page`（完整 Puppeteer）→ `code`（全 Node）→ relay（用户真实浏览器）。
- helper 不够就降级，别硬凑。
- relay 操作属于用户，注意边界。

## 规范

### 取数据

1. 挂监听：`page.on('response', handler)`，按 URL 特征过滤 API 端点。
2. 触发请求：导航、滚动、切 tab 都会发新请求，监听器持续捕获。
3. 解析：`await resp.json()`，先看响应形状，再取目标字段——避免一次拉全量烧上下文。
4. 只有 API 拿不到（无网络请求、数据在服务端渲染）才退回 DOM 提取。
5. 页面内容不完整（懒加载、分页、自动翻译）时，优先走网络层拿原文全量，不要逐个处理渲染层问题。
6. 时间过滤用 API 时间戳，不用 DOM 里的相对时间。

### 理解页面

- 用 `observe`/`ariaSnapshot` 读结构，截图只用于外观验证。
- 页面内容与预期不符时，先检查语言/区域设置、登录态、视图切换。

### 操作页面

- 操作前确认目标存在且唯一（模糊匹配时先查再点，别点第一个）。
- 表单写入后必须验证：autocomplete、React controlled inputs、masked 字段会静默吞字符——type/fill 后读回值，select 后读回值。
- 自定义控件（非原生 select 的下拉/选择器）用"点触发器 → 点选项 → 验证"流程，不要当原生控件操作。
- 不要用 JS 提交表单：现代站点拦截，静默丢弃，用真实点击。
- 导航或 re-render 后重新获取句柄，旧 ref 会失效或错配。

### 验证

- 数据任务：核对数据量与预期一致。
- 操作任务：验证状态变化。
- DOM 与 API 不一致时以 API 为准。

## 排查

- 监听器没捕获到：先确认请求确实发生，再检查 URL 过滤条件。
- 滚动不加载：换键盘事件或直接导航触发，或走网络层拿全量。
- 操作没生效：确认元素存在、句柄未失效、页面未导航。
- 写入没生效：autocomplete/controlled 输入吞字符，读回值确认。
