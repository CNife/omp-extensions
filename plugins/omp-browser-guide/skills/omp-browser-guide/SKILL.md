# omp-browser-guide

本技能把跨站点通用的策略经验前置，避免每次冷启动都踩一遍坑。

## 心智模型

- **network-first**：页面数据几乎总是来自 JSON API。先挂 `page.on('response')` 抓 API 响应，比 DOM 提取更可靠——完整文本、结构化字段、绕过渲染层干扰。DOM 提取是兜底，不是首选。
- **响应即数据**：API 响应里的字段就是最终数据，不需要再解析渲染后的 DOM。递归遍历 JSON 提取目标字段，一次拿到全部。
- **渲染层是干扰源**：自动翻译、懒加载、分页 tab——都是渲染层行为，不是数据本身。network-first 天然绕过它们；被迫走 DOM 时才逐个处理。
- **tab 语义**：站点常把内容分到独立 tab，每个 tab 对应不同 API 端点。切 tab 会触发新的网络请求，监听器继续捕获即可。

## 规范

### 提取：先 network，后 DOM

1. 挂监听：`page.on('response', handler)`，按 URL 特征过滤 API 端点。
2. 触发请求：导航、滚动、切 tab 都会发新请求，监听器持续捕获。
3. 解析：`await resp.json()`，递归遍历找目标字段。
4. 只有 API 拿不到（无网络请求、数据在服务端渲染）才退回 DOM 提取。

### 滚动与懒加载

- 懒加载列表对程序化滚动不敏感时，换键盘事件或直接导航触发。
- 滚动方向：时间线是倒序，往旧方向翻页会远离目标窗口，先确认方向再翻。
- 滚动加载慢时，用 `waitForResponse` 等目标 API 响应，而不是固定 sleep 循环。

### 自动翻译

- 站点按浏览器语言自动翻译内容，DOM 里是翻译文本，`lang` 属性会变。
- 恢复原文：批量点"显示原文"按钮，或直接走 network-first 拿 API 原文。
- 判断依据：`lang` 属性不是目标语言，或文本里有"翻译自"标记。

### 分页与独立 tab

- 内容分到独立 tab 时，切 tab 触发对应 API 端点，监听器继续捕获。
- 时间过滤：API 的 `created_at` 字段是权威时间戳，按它过滤窗口，不要用 DOM 里的相对时间。

### 验证

- 提取完成后，核对数据量与预期一致，确认没有漏掉独立 tab 的内容。

## 排查

- 监听器没捕获到：先确认请求确实发生，再检查 URL 过滤条件。
- DOM 提取与 API 数据不一致：以 API 为准，API 是数据源，DOM 是渲染结果。
- 滚动不加载：换键盘事件，或直接导航触发新请求。
