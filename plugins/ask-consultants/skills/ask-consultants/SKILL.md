你召集顾问团：让多个不同模型的顾问对同一问题各自独立出意见，你负责权衡分歧、裁决出最终结论。

## 成员

成员是触发本技能的那条消息所列 ^模型 标签对应的代号：在 task 工具描述里按模型选择器与代号一一对号。此前注册、但不在本次清单里的代号不派发。

完成判据：派发集合与本次清单一一对应。对不上号（一个代号都没有）时，停止并告诉用户运行 `/ask-consultants` 或在消息里用 `^模型` 点名；不要用 scout/reviewer 等普通 agent 顶替成员。

## 任务书
每个成员收到同一份任务书。成员走通用 task 模板，没有顾问人设，立场必须随任务书携带：

1. 评审对象：原样附上用户的问题与方案材料，不删减、不转述；材料里出现的成员名照原样保留（那是用户写的，不属于你添加的泄漏）。
2. 背景：派发前由主对话把评审所需的背景搜集齐——相关文件与代码位置、关键约束、已有讨论与决定——按交接文档的写法组织进任务书：面向本次评审裁剪，与评审无关的不写；大块材料引用文件路径供成员定点读，不整段照抄；敏感信息（密钥、口令、个人信息）脱敏。成员不为摸清背景花检索成本。成员用工具做的实证只核查任务书里的判断，不替代背景搜集。
3. 立场：
   - 顾问不是执行者：只调查、只出意见。用工具读代码、跑只读命令做实证后再下判断；不修改任何文件、配置或状态。
   - 按序评审：完整性（这条路线能否端到端到达目标）→ 盲区（被当作前提的条件、没人检查的边界）→ 替代路线（只在会改变结论时给出）。
   - 判定先行：第一行给判定，再给依据；方案成立就一句话说成立，不硬找问题。
   - 用中文写。

完成判据：任务书自包含——背景已搜集齐、随任务书携带，成员不需要任何会话上下文即可开始评审。

## 派发
用 task 工具一次调用并行派发（tasks[] 数组），agent 填各成员代号，每个成员独立 spawn。

独立性指评审过程互不可见：不向任何成员的任务书添加其他成员的代号、模型或意见；用户材料原样携带的内容不在此列。汇总只发生在全部报告返回之后。

完成判据：本次清单中每个成员各得一份报告，或一条如实记录的失败原因（注明失败成员与原因）。不编造失败成员的意见。

## 汇总
你是主位者：汇总的产出是你的权衡结果，不是成员意见的摘编。不复述各成员的报告，不标注观点出自哪位成员——用户在乎的是分歧本身，不在乎出处。

全部报告收齐后，直接输出给用户：

1. **结论** — 第一行给最终结论；其后是你权衡后的裁决：采纳哪条路线、否决哪些、为什么。成员意见是输入，判断由你负责。
2. **分歧** — 成员间实质相左之处：分歧点是什么、根源在哪、你如何裁决。没有实质分歧就一句话说明一致，不硬找差异。

完成判据：用户读到的是你的最终结论与分歧的裁决，而非成员意见的复述；篇幅由结论与分歧决定，与成员数量无关。
